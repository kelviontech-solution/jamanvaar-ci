## 2. Method used in run 2

1. **No installs, no repo edits.** A throw-away Vite config per app lived in the session scratchpad (outside the repo): it imports the app's own `vite.config.ts`, redirects Vite's cache to the scratchpad, and adds two resolve aliases:
   - `@jamanvar/tauri-plugin-apk-updater` → the real in-repo `packages/tauri-plugin-apk-updater/guest-js/index.ts` (the workspace package exists but was never linked into `node_modules`);
   - `@tauri-apps/plugin-updater` and `qrcode` → tiny stubs (those npm packages are not installed). The `qrcode` stub draws a **non-scannable placeholder**; no QR rendering was assessed anywhere.
2. Servers were started with `node node_modules/vite/bin/vite.js --config <scratch config>` on the apps' usual ports, rendered with the machine's installed Chrome via the DevTools protocol (a script in the scratchpad), then stopped. Evidence is under `evidence/<app>/<PAGE-ID>-<state>-<w>x<h>.png`; raw logs in `log-pass1.json`, `log-pass2.json`, `log-pass3.json`.
3. Backend (`http://localhost:4000`, relay `:5178`) was not started: it needs Postgres/Prisma and would write data files. No production URL is a default in any app (`cloudClient.ts`, `client.ts` default to `localhost:4000`), so no request left the machine.
4. Authentication was never bypassed; no tokens or storage were forged.

Tools **not** available/installed: Playwright (module absent; existing `tooling/qa/*.cjs` scripts require it), Lighthouse, axe. No performance measurements were taken.
