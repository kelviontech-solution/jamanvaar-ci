## Implemented behavior

Windows uses Tauri's official signature-verifying updater for optional, mandatory and kiosk manual update actions. Updates require an operator action; startup no longer silently installs before storage initialization. The updater checks the offered version and signed installer application/version/x64 filename, displays progress and actionable failure, and flushes local storage before installer handoff. POS, Captain and kiosk reject updates while an unfinished order is present; the check repeats after download. Active print jobs and failed persistence also block installation. Windows uses the installer's restart behavior. On the next native launch, the actual native version must equal the expected version before reporting success.

Android requests the supported unknown-app-install permission, retains download state, verifies checksum, package, release/debug flags, signing certificate, increasing version code and compatible native ABI, then waits for an explicit foreground installer action after local data is saved. The Android system installer retains user consent. A completed download or an opened installer is never displayed as an installed update. Java and Android SDK/NDK were initially missing; verified tool downloads now reside outside the workspace. All five unsigned arm64 release APKs compiled through Kotlin, R8, resource shrinking and release lint. KDS was rebuilt with the final backup policy. Actual signing/device acceptance remains separate.

The backend validates canonical release versions, platform metadata, hosted native checksums and Windows minisign signatures before publishing. Validation permits only explicitly allowlisted public HTTPS artifact hosts, resolves and pins public IPv4 addresses, and rechecks redirects. Windows signatures must describe the correct application's original NSIS filename and version. Compatible platform selection prevents a newer Android release hiding the latest usable Windows release. Public manifests disable caching. Authorized platform administrators can pause a release; paused releases leave subsequent heartbeat/manifest selection. Super Admin shows bounded device-reported post-install results. These reports are diagnostics supplied by clients, not remote attestation.

CI uses an external Windows signing runner with the unchanged updater key outside the checkout and GitHub Secrets. Authenticode is checked separately. Android release builds enable supported R8/resource shrinking with Tauri reflection keep rules, pin the generated Gradle distribution checksum, disable automatic Android backup of app-private activation/session data, and packaging checks the preserved application ID, version, ABI, non-debug status and signing fingerprint. Disabling system backup does not clear local SQLite/OPFS during in-place upgrades or alter the explicit Branch Core backup feature; OEM device-transfer behavior still needs device acceptance. Release inventory records each application's version instead of treating the Admin version as every app's version. POS, Restaurant Admin and kiosk Rust lockfiles are aligned to KDS's already audited dependency resolution; Captain already matched. Locked metadata and subsequent builds validate this graph. Generated Android bridge/cache output remains ignored rather than shipped as source.

POS's tracked Local Core binary lacks evidence that it was built from current authenticated source. CI now refuses to package it without matching source/binary hashes and an authenticated-endpoint smoke-test record. The guard is a provenance consistency check, not a compiler or proof that a supplied record is truthful. A trusted source build and runtime acceptance remain required. Restaurant Admin's current Tauri configuration does not declare this external binary. Eleven older wrapper packaging/deployment entry points now stop before any output mutation: they cannot produce an alternative package lacking Tauri updater/identity compatibility or replace local installations. Their source is retained for migration reference; existing installed wrappers are unchanged.

## Remaining release blockers and limitations

1. **High:** No existing-installation-to-new-installation upgrade has been performed on Windows or Android. No installation/restart, process-kill, disk-full, hardware receipt printing or rollback test has been completed on a real terminal. Historical wrapper/MSI migration to Tauri NSIS is unproven.
2. **High:** Configure the restricted Windows runner, preserved external updater key, usable Authenticode signing configuration and verified trust/timestamp behavior. Configure the original Android keystore and recorded predecessor signing certificate. Local Java/SDK/NDK bootstrap and all five native build checks are complete; signed installer/APK output and installed-device acceptance still require recorded results. The user's instruction to proceed does not supply or authorize replacement of the original Android signing identity.
3. **High:** POS needs a verified current Local Core source build. The legacy relay's file/static asset paths depend on `__dirname`; SEA packaging and update data preservation must be tested before generating provenance. Do not rename storage paths to bypass this check.
4. **High:** The backend verifies APK archive/hash, while CI and the native plugin validate APK identity/certificate/version. Backend publication does not independently parse and validate an APK's full signing identity. Host access is allowlisted but hosted artifacts should also be immutable.
5. **Medium:** Legacy AppRelease rows remain published for compatibility, with a null verification timestamp. Review/pause incomplete historical rows before rollout. New validation cannot retroactively make older artifacts valid.
6. **Medium:** Available lifecycle is published/paused and stable-channel offers, not staged percentage rollout, a complete draft/build/sign/upload state machine, or automatic rollback. Pausing prevents new offers; it does not remotely stop an installer already downloaded and handed off.
7. **Medium:** Artifact validation buffers up to 256 MiB per request. Provision memory and limit simultaneous publication requests. IPv6-only artifact hosts are unsupported. Client telemetry can be stale or forged and is not a security authorization input.
8. **Medium:** R8 does not obfuscate bundled JavaScript or Rust, and reflection keep rules deliberately retain essential bridge classes. Optimized EXE/APK files can still be reverse engineered. No absolute anti-tampering or 10/10 security claim is made.
9. **Medium:** Signing environments must enforce protected branch/environment controls outside the workflow file. Authenticode/Android signing secrets are now scoped to validation/signing steps instead of npm/frontend steps. The Windows build still executes trusted build dependencies on the signing runner; a separately isolated signing service or hardware-backed signer is stronger protection against a compromised build dependency and has not been provisioned here.

ADB reported no connected devices. No original APK/signing archive was found in the checked Downloads/Documents top-level locations; this is a bounded search, not proof that the original keystore is lost. See [DEVICE_ACCEPTANCE_AVAILABILITY.json](evidence/DEVICE_ACCEPTANCE_AVAILABILITY.json).

See [DEPLOYMENT.md](DEPLOYMENT.md) for the required rollout and predecessor acceptance sequence. Production migrations, signing, publication and device upgrades have not been performed by this task. The local native compile outputs use the existing workspace frontend build configuration and are not substitutes for CI's explicitly validated public release API/QR URLs.
